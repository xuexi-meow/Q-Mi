# 红薯离线学习准备与评测设计

日期：2026-11-09，Asia/Shanghai。

状态：已结合用户指定的数据来源整理，等待书面设计确认。本文描述待实现功能，不代表已经运行采样、模型评测或微调。

## 1. 目标与范围

新增独立本地命令，完成：

`只读历史采样 → 离线接话 → 人工审核和改写 → 训练/测试数据导出`

第一阶段是训练准备与评测，不更新模型权重，不自动提交平台微调任务，不自动把样本写入红薯的在线记忆或提示词。

用户指定的首批来源：

- 群聊 `928952016`。
- 群聊 `903524535`。
- 默认最近连续七天，即采样时刻向前 168 小时；采样开始时固定截止时刻并写入批次清单。时间展示采用 Asia/Shanghai，数据保存完整时间戳。
- 用户继续与红薯私聊不受影响。没有指定私聊账号，首批不读取任何私聊；未来使用显式私聊账号允许列表添加，不自动扩大到全部管理员或所有好友。

候选方案比较：

- 独立本地命令：首版采用，便于与 QQ 运行流程隔离、重复执行及自动化测试。
- 集成 WebUI 审核：可减少手工编辑，但增加页面、鉴权和运行时接口；首版不做。
- 直接自动训练和上线：缺少审核及回归数据，不在当前范围。

## 2. 隔离与安全边界

- 不启动 QQ 服务、NapCat 客户端、Manager、自唤醒、浏览器或工具执行循环。
- 数据库只读打开，不使用会建表和迁移的 `storage.Open`，不修改在线数据库。
- 对不存在的数据库、缺失的必需列、无可用来源明确报错，不创建空库掩盖问题。
- 不复制正在写入的 SQLite 主文件作为快照；以 SQLite 只读事务获取一致的读取结果，保留 WAL 可见性。
- 不调用 QQ API、发消息、请求历史补拉或下载媒体。
- 采样、审核和导出不联网。离线试接话若使用云模型，仍会上传筛选后的上下文并产生 API 费用，必须显式启用。
- 初次交付只运行本地功能及使用模拟 HTTP 服务的测试。真实云端试接话须再次确认模型、样本范围与调用上限。
- 不输出或保存 API 密钥；真实数据、审核内容和生成结果保存在已忽略的工作区下，不加入 Git。
- 来源允许列表只表示账号使用者指定了范围，不替代群成员隐私、数据使用和上传授权检查。

## 3. 命令与文件边界

命令入口为 `cmd/offline-learn`，业务逻辑放在独立的 `internal/offlinelearn` 包。默认数据目录为 `agent/workspace/offline-learning`。

命令分为四步：

1. `collect`：明确数据库路径、两个群号、时间窗口和条数上限，生成本地候选批次。
2. `shadow`：显式启用 API、指定模型和 API 地址/密钥环境变量，有限次生成接话或沉默决策，只保存结果。
3. `review`：通过案例 ID 记录认可、拒绝、改写或沉默决策，可重新运行修改判断。
4. `export`：只导出通过人工审核的样本，生成训练集、测试集和批次报告。

首批两个群号写入可读的本地操作示例，不修改机器人在线配置。代码不把这两个群硬编码成永久授权来源。

每个批次包含：

- `manifest.json`：格式版本、批次 ID、允许来源、固定时间窗口、参数、计数和跳过原因。
- `cases.jsonl`：匿名化上下文、候选 ID、媒体/截断等质量标记和会话分组。
- `predictions.jsonl`：模型身份、生成时间、发言/沉默决策、候选正文和可用的用量统计。
- `reviews.jsonl`：按案例 ID 保存人工决策、最终正文和可选纠正说明。
- `exports/`：训练及测试 JSONL、独立沉默决策集和导出报告。

全部文件仅作为数据处理；其中的聊天内容和反馈不作为本地命令执行指令。

## 4. 历史选择与案例构造

- SQL 必须同时限定 `chat_type = group`、群号允许列表、时间和撤回状态。
- 默认排除已撤回消息；不读取群外、私聊或通知表作为上下文。
- 查询顺序固定为时间和消息 ID，避免相同时间下顺序不稳定。
- 首批默认每群读取至多最近 2000 条，整批至多生成 100 个案例，各群尽量均衡；报告实际覆盖范围和上限造成的省略。
- 在单个群内按连续会话片段处理，间隔超过 30 分钟切段。一个案例至多包含锚点及之前共 12 条消息，不跨群拼接，不向模型展示未来回复。
- 以收到的有文字聊天作为候选锚点。自己已经发出的回复仅可作为本地审核参考，不能自动成为正面训练目标。
- 真人聊天仅提供语境和待审核素材；不因来源为真人就自动认可，也不自动推断某个账号一定是真人。
- 首版不对“什么最有趣”作不可审查的模型自动评分；采用有界、确定性的抽样，并保留人工丢弃入口。
- 非文本消息用中性占位符表示，不下载、不读取私有图片链接；依赖缺失图片才能理解的案例必须标记，未经人工补足或确认不得导出为正面样本。
- 单条上下文正文最多 1000 个 Unicode 字符，案例正文总计最多 12000 个 Unicode 字符；截断必须记录标记，不能默认为完整事实。
- 同一原始案例重复采集时使用稳定来源身份生成案例 ID；不依赖模型回复内容去重。

## 5. 匿名化与人工审核

- 发送者使用批次内、会话内一致的代称；红薯单独标识，其他人不混成同一个角色。
- 群号、QQ 号、消息 ID 等原始定位信息仅保存到本地溯源映射，不进入用于 API 试接话的正文或默认训练导出。
- 结构化处理 @、引用及文本消息段；无法解析的关系保留“引用不可用”等标记，不猜测被引用的人或原文。
- 对显式联系方式、邮箱、凭据样式等作尽力脱敏，并在报告中声明无法保证消除所有隐私。人工审核仍是上传和导出的必要环节。
- 案例状态默认待审核，生成成功、自评高分、群友回复或表情互动均不等于人工认可。
- 正面标签优先使用用户确认或纠正后的红薯回应，不复制他人的身份、私人经历和特定关系。
- 沉默保留为显式的“不发送”决策，不把“不回复”“finish”等文字当作应发到 QQ 的回复正文。

## 6. 离线接话

- 使用有限的结构化输出协议：`action` 为 `reply` 或 `silence`；仅 `reply` 可以有非空 `text`。
- 请求中没有 QQ 操作工具，也不运行模型返回的工具调用。
- 可复用现有纯 HTTP 模型客户端，但不得构造在线 Manager、读取在线私人记忆或启动机器人。
- 模型配置必须显式指定；密钥从命令指定的环境变量读取。首版不隐式选择在线模型池或切换供应商。
- 默认单并发，最多 20 个未生成案例，每次输出上限 256 token、超时 120 秒；用户可显式降低限额。失败不无限重试。
- 已生成案例默认跳过。用户要求重跑时保存新版本，不能无提示覆盖先前评测。
- 请求提示只包含表达所需的人设、当前匿名化片段和发言/沉默协议，不附带完整在线工具说明、跨群上下文或管理员隐私。
- 生成结果中的内部标签、历史行头、非法结构或工具调用标为不可直接采纳，不能自动进入正面样本。
- 离线模式与真实工具环境不同，报告中必须说明它不能证明完整智能体的工具使用能力。

## 7. 导出、版本与防泄漏

- 导出版本固定读取同一份案例、评测和人工审核快照，记录输入摘要与模型身份。
- 默认仅人工确认的有效文字回复进入通用 `messages` 形式的 SFT JSONL：必要上下文作为输入，最终回复作为唯一 assistant 目标。
- 该格式是通用中间产物，不承诺直接满足所有托管平台的模板、工具调用和最低样本数要求。
- 沉默案例输出到单独的决策训练/评测文件；未经目标平台适配，不冒充可直接上线的 `finish` 工具调用训练数据。
- 可导出用户明确选择的较好/较差回应对；不要求首版自动执行 DPO 训练。
- 以完整会话片段分配训练集/测试集，禁止将同一片段的重叠上下文拆入两侧。分配可复现，默认约 80%/20%。
- 数据不足以形成独立测试片段时明确报告不足，不能声称有有效的独立测试结果。
- 原始数据库、批准样本、测试集及既有导出默认不覆盖。新版本采用独立目录，写入失败不能留下看似完整的批次。
- 后续采样不自动修改 `chat_style.md`，也不把待审核案例当成红薯已经学会的内容。

## 8. 验收与测试

采用测试先行，使用临时 SQLite 数据库和本地模拟模型 HTTP 服务：

- 白名单严格隔离这两个群之外的消息及全部私聊，时间和数量限制有效。
- 撤回排除、稳定排序、同群上下文、未来回复遮蔽和均衡采样符合要求。
- 只读打开不迁移或修改原数据库；数据库不存在、损坏或缺表时错误明确。
- 匿名化、Unicode 限长、媒体缺失标记及重复采集行为可验证。
- 默认操作不联网；shadow 不得发起 QQ 操作，未显式开启不能请求云模型。
- 模型调用上限、超时、非法结构、工具调用、失败重试限制及结果保存可验证。
- 未审核、被拒绝、缺必要媒体或非法正文不进入正面训练导出。
- 沉默不变成聊天正文，导出只以批准后的红薯回复为目标。
- 同一会话片段不会跨训练/测试分区，导出可复现，回滚不影响在线机器人。

实际交付须报告采样条数、候选数量、跳过原因和是否调用了真实模型。没有模型训练任务时，不能称为“已完成模型微调”。

## 9. 当前不做

- 自动采集全部私聊、所有管理员会话或其他群。
- 自动上传完整数据库、媒体、凭据或私密身份映射。
- 自动云端训练、购买算力、创建付费部署。
- 自动在 QQ 试发消息或替换线上模型。
- 将全部聊天写入固定提示词，扩大在线上下文预算。
- 无人工确认的自评、自训、自上线循环。
